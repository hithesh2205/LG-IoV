    High-Level Architecture (The Pipeline)
Goal: Perform secure, privacy-preserving collaborative learning with every model layer/parameter fully encrypted under FHE, eliminating transport-layer ECDH/AES security overhead.
• Step 1: Preprocess and scale datasets (percentile clipping, z-score)
• Step 2: Dirichlet non-IID client sharding (alpha = 0.3)
• Step 3: Initialize Global Model (ChebyKAN) and register client vehicles
• Step 4: Encrypt Global Model layers separately under FHE (Simulated CKKSVector)
• Step 5: Broadcast global layer-wise FHE ciphertexts to active clients
• Step 6: Perform local client training and package layer-wise FHE client updates
• Step 7: Homomorphic FedAvg + Multi-Krum aggregation layer-by-layer directly on ciphertexts

Core Model & Cryptographic Security
The Model: Pure Chebyshev KAN (ChebyKAN)
Chebyshev Polynomial KAN: Replaces splines with Chebyshev polynomials of the first kind. Global model has only 44,164 parameters.
Slices features directly into sequential Chebyshev basis projection layers (T_n(x) polynomials calculated recursively).

Cryptographic Security (Layer-wise FHE):
No Transport-Layer AES/ECDH: Handshakes, key exchanges, and symmetric transport encryption are completely removed.
Full Layer-wise FHE Encryption: Clients encrypt each weight and bias tensor separately using Simulated CKKS FHE vectors.
Homomorphic Aggregation: Aggregator server aggregates weights and biases layer-by-layer directly on ciphertexts, preserving privacy.

--- Slide 12 ---
Chebyshev KAN & Adapting Weights
Global Model Layout:
Features input scaling, recursive Chebyshev polynomial basis projection layers (T_0 to T_degree), stacked Chebyshev KAN Linear Layers with LayerNorm and Dropout, followed by a final output ChebyKAN layer mapping to classes.
Loading Weights with strict=False:
The server handles bootstrap weight adaptation to match the exact class structure of the target dataset, allowing the Chebyshev KAN model to support different output class dimensions.

Total Parameters: 44,164 (CAN-VTC Configuration)

• Input Chebyshev KAN Layer (46 -> 64 hidden nodes):
  - Chebyshev weights: 64 * 46 * 5 = 14,720 parameters
  - Base weights: 64 * 46 = 2,944 parameters
  - Bias weights: 64 parameters

• Hidden Chebyshev KAN Layer (64 -> 64 hidden nodes):
  - Chebyshev weights: 64 * 64 * 5 = 20,480 parameters
  - Base weights: 64 * 64 = 4,096 parameters
  - Bias weights: 64 parameters

• Output Chebyshev KAN Layer (64 -> 4 class outputs):
  - Chebyshev weights: 4 * 64 * 5 = 1,280 parameters
  - Base weights: 4 * 64 = 256 parameters
  - Bias weights: 4 parameters

--- Slide 14 ---
Layer-wise FHE Cryptography
CKKS Homomorphic Encryption Scheme:
Supports additions and scalar multiplications directly on real-numbered ciphertext vectors. The private key remains secure on the client (vehicle) and is never transmitted to the server.
Full Layer-wise FHE Processing:
Every weight and bias tensor is flattened, encrypted as a SimulatedCKKSVector, and processed. The server performs aggregation on each layer's ciphertext separately, maintaining zero plaintext exposure.

--- Slide 15 ---
Homomorphic Aggregation & Outlier Filtering
Homomorphic FedAvg Aggregation:
Aggregates updates by evaluating additions and scalar weights homomorphically layer-by-layer:
Enc(W_layer_global) = sum( w_i * Enc(W_layer_i) )
Decryption is done locally on vehicles using the FHE private key.
Homomorphic Multi-Krum Outlier Rejection:
Aggregator server computes Euclidean distances between the encrypted weight updates (concatenating all layer ciphertexts) to run scoring and filter out Byzantine clients before aggregation, protecting against model poisoning attacks.
End-to-End Privacy: No transport keys or AES; security is guaranteed by FHE mathematical bounds.
